# Parley SQL ideas

> Ideas for SQL on IBM i (the SQL window, Parley's SQL add-on and Parley SQL) that might become requirements later.
> Nothing here is planned or promised: the plan is [ROADMAP.md](ROADMAP.md). Look an idea up with `grep -n`
> (`"| IDEA-13 "`) rather than reading the whole file. The terminal's ideas are in [../IDEAS.md](../IDEAS.md).

## How an idea moves on

- A new idea gets the next free `IDEA-n` from the last line of [../IDEAS.md](../IDEAS.md), which is then moved on: one
  sequence for both files. IDs are never reused or renumbered.
- When an idea is picked for a phase, write it as one or more requirements in the roadmap (§5, next free ID of the
  area) and mark the row here *"→ R-XXX-n"*. Remove the row once its requirements are done; the number stays used.
- An idea that would change a decision (either roadmap) says so; the decision is taken before it is built.

## Data on the host

| ID | Idea |
|---|---|
| IDEA-13 | **SQL against the open session's host.** A "SQL…" window (Tools menu, a shortcut) for the connected session: type one or more statements, run them, see result sets in a grid (sortable, copy cells/rows, export CSV), messages and SQLSTATE for errors, row counts for updates, and a history of statements per session. It reuses the session's host, TLS setting and CA file; the user and password are asked for (Parley keeps none, D16). *How*: a second connection to the IBM i database host server (`QZDASOINIT`, port 8471, or 9471 with TLS; signed on through the sign-on server, 8476/9476), the protocol JTOpen and the ODBC driver use; built sans-I/O in `parley-core` (or its own crate) as the 5250 protocol is (D4), tested with recorded traffic. *Open questions*: the host-server protocol is documented mainly by JTOpen's source, so the first step is to check what can be implemented from public documentation; fall back to the installed IBM i Access ODBC driver (needs the user to install it); commit control (autocommit on by default, Commit/Rollback buttons); a guard for statements that change data (confirm `DELETE`/`UPDATE` without `WHERE`); a row limit with "fetch more". It would be the second kind of connection to a host, so it needs a decision next to D4/D6. *Probed 2026-11-13 without signing on (R-NET-8): the owner's IBM i (7.3) offers the host servers and DRDA (446) without TLS only (9471, 9476 refused; 447 not reachable), password level 0, no Mapepire (8076) and no SSH; PUB400 (7.5) offers the host servers with and without TLS (certificate trusted), DRDA on 446, password level 3, a Jetty server on 8076 with a self-signed certificate (likely Mapepire), and SSH on 2222. So the host servers and DRDA reach both; Mapepire only PUB400. Route chosen: the native host-server client (D19).* *→ R-SQL-1..13, R-NET-9 (Phase 5). Running SQL changed to a Java helper with JTOpen (D20, 2026-11-13).* |
| IDEA-25 | IBM i Services views built on IDEA-13: the job log of the session's own job, the spooled files of the user (open one as text or PDF), and the message queue behind the "message waiting" indicator, from the `QSYS2` SQL services. |
| IDEA-26 | Data transfer: download a table or a query result to CSV or Excel, and upload a CSV into a table, as Access Client Solutions' Data Transfer does; built on IDEA-13. |
| IDEA-28 | **A stand-alone SQL client** (the owner, 2026-11-13; picked 2026-11-14 as Parley SQL for Phase 11, R-SQL-45..47, D26): the SQL add-on offered on its own, for people who need SQL on IBM i but no 5250 session — the same Java helper with JTOpen (D20) and SQL window, started directly with a host, user and TLS setting rather than from a connected session, possibly as its own program and installer. The pieces already stand apart: the engine in `parley_core::sql`, the window in `parley-ui-egui`'s `sql` module, the jars in `helpers/`. *Open:* one app with a choice at start or a separate program; how saved sessions and the history are shared; its own name. |
| IDEA-29 | **Know the database in the SQL window** (the owner, 2026-11-13; picked for Phase 8, R-SQL-30..37): a schema browser of libraries, tables, views, procedures and columns (`QSYS2` catalog); table and column names completed while typing; the DDL of an object (`QSYS2.GENERATE_SQL`); hovering a name shows its columns. |
| IDEA-30 | **IBM i tools in the SQL window** (the owner, 2026-11-13; picked for Phase 8, R-SQL-30..37): the SQL job's library list and current schema; CL commands through `QSYS2.QCMDEXC`; the SQL job's job log after an error; an SQL message's full second-level text (SQL0204 explained, not just its code). |
| IDEA-31 | **Parameters and more from results** (the owner, 2026-11-13; picked for Phase 9, R-SQL-38..42): a form for `?` and `:name` markers, remembered per statement; quick charts from a result; copy as a Markdown table, `INSERT` statements or JSON; compare two results; a hex/EBCDIC view of `FOR BIT DATA` columns. |
| IDEA-32 | **Several systems at once** (the owner, 2026-11-13; picked for Phase 10, R-SQL-43): run one statement on several saved sessions and see the results side by side (test against production). |
| IDEA-33 | **An SQL assistant** (the owner, 2026-11-13; picked for Phase 10, R-SQL-44, R-ADD-3, D25): plain language to SQL with the catalog's table and column names, opt-in. *Needs a decision first:* what may leave the machine (names only, never data?), which model and account, and how it is turned off. |
| IDEA-34 | **A code editor of Parley's own** (the owner, 2026-11-14, from the ideas after Phase 13): an editor widget instead of egui's text field, for line numbers, a gutter with a ▶ per statement and the last run's rows, time or error, the line of an error from the position Db2 gives, folding and several cursors, and speed on long scripts (the text field lays out all the text every frame). Smaller ones that may come first: a line-number gutter beside the text field (only while lines do not wrap); completion of keywords, of columns through table aliases and of snippets; a procedure's or function's parameters while `CALL X(` is typed (`SYSPARMS`); scripts not saved coming back after a crash; formatting choices (indentation, keyword case, commas first). *Decided (D28, 2026-11-14): stay on the text field with a gutter of Parley's own; picked for Phase 14 (R-SQL-61..68): line numbers, ▶ and outcomes, completion when asked and with snippets, parameters, the word under the cursor, Ctrl+D, trailing blanks.* Left here: folding, several cursors, an error's exact position, completion of a WITH's names, scripts not saved coming back after a crash, formatting choices. |
