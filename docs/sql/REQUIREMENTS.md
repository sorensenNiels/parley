# Parley SQL requirements

> The agreed text of every SQL requirement that is implemented **and verified**: when one is, its row moves here from
> [ROADMAP.md](ROADMAP.md) (open requirements) and [FEATURES.md](FEATURES.md) records how it was verified. The
> terminal's are in [../REQUIREMENTS.md](../REQUIREMENTS.md).
> Look a requirement up by ID (`grep -n "R-SQL-7 " docs/sql/REQUIREMENTS.md`) rather than reading the whole file.

| ID | Requirement |
|---|---|
| R-SQL-13 | **JTOpen, checked and shipped** (2026-11-13; D20). Before anything is built on it: JTOpen's licence (IBM Public License 1.0) is read for shipping the unmodified `jt400.jar` with an MIT/Apache app, and the result recorded in D20; if it does not allow that, the owner decides again. Then a pinned JTOpen release from Maven Central, its SHA-256 checked by the build, and Parley's helper jar go into the installers beside the app (cargo-packager resources, docs/RELEASING.md), with the IPL text beside the font licences and a line in README.md. Building the helper needs a JDK (11 or later) on the build machines and in CI; `make verify` compiles it. |
| R-SQL-12 | **Java, found or explained** (2026-11-13; D20). The SQL add-on runs the helper with Java 11 or later: the path set in Settings ▸ Add-ons, else `JAVA_HOME`, else `java` on the `PATH`. Settings ▸ Add-ons shows which Java was found and its version. Without one, Tools ▸ SQL… opens a short explanation with a link to a free Java (Eclipse Temurin) instead of failing; nothing else in Parley needs Java. |
| R-SQL-11 | **The SQL helper and its protocol** (2026-11-13; D20). A small Java program (`helpers/sql`, Parley's own code) that Parley starts when an SQL window opens and stops when it closes; it also ends when its input closes, so it never outlives Parley. They talk in JSON, one object per line on stdin/stdout, with a protocol version in the first exchange: connect, run, fetch more, cancel, commit, rollback, autocommit on/off, close; each answer is a result or an error with SQLSTATE, SQLCODE and the message text. The user and password go only through stdin, never on the command line or in the environment, and never reach a log or an error. The helper's stderr is kept only to show when it fails. Parley's side (`parley-core`, sans-I/O as D4) is tested against a fake helper; the helper is checked against the owner's IBM i. |
| R-SQL-3 | **A database connection** (2026-11-13; D20, was D19). The helper connects with JTOpen's JDBC driver to the session's host, over TLS when the session's TLS is on (Java's trust store plus the session's CA file, turned into a trust store for the helper; how this compares with D6's operating-system trust store is settled while building), with ISO dates and times, `*SQL` naming and the user's default library list, and reports the server's job name. One connection per SQL window. A refused sign-on is reported as JTOpen words it, and never retried. |
| R-SQL-4 | **Running statements and reading results** (2026-11-13; D20, was D19). The helper prepares and runs a statement; for a query it fetches rows in blocks of 500 up to the window's limit and sends them as text: DECIMAL and NUMERIC exactly (no floating point), dates, times and timestamps in ISO form, binary as hex, NULL apart from an empty string, LOBs as "(LOB)"; each column with its name, type, length, scale and whether it may be NULL. A statement that is not a query gives its row count. A running statement can be cancelled. Tested with `æøå` in CCSID 277 data and a value at each type's limits on the owner's IBM i. |
| R-SQL-5 | **Commit control** (2026-11-13). Autocommit is on when the window opens. With it off, statements run under commit control (`*CHG`) and Commit and Rollback are offered; closing the window or disconnecting with uncommitted changes asks Commit, Roll back or Cancel. |
| R-SQL-6 | **The SQL window** (2026-11-13). Tools ▸ SQL… and a bindable function `sql` open it for the connected session's host, as a window of its own beside the main one (an egui viewport), so the 5250 screen stays usable (the owner, 2026-11-13). Opening asks for the user and password (Parley keeps none, D16); the user defaults to the last one typed for this session in this run of Parley. The window's title names the session and the database job; without TLS a warning line says the statements and results travel unencrypted, and nothing more is asked (the owner, 2026-11-13). Disconnecting the session closes the window (asking first under R-SQL-5). |
| R-SQL-7 | **Writing and running** (2026-11-13). A monospace editor; Run (Ctrl+Enter) runs the selection, or the statement under the cursor (statements end with `;`); Run all (Ctrl+Shift+Enter) runs them in order and stops at the first error; Cancel (Esc) stops a running statement (R-SQL-4). A history of the statements run (the last 100 per saved session, kept in the settings between runs of Parley (the owner, 2026-11-13), never with results) is listed beside the editor; one click puts a statement back in the editor. |
| R-SQL-8 | **Results** (2026-11-13). Each query's rows in a grid: column names with their types on hover, NULL shown apart from an empty string, numbers right-aligned, dates in ISO form. At most 1000 rows are fetched at first ("1000 rows shown · Fetch more"); a click on a column heading sorts the rows fetched. Copy a cell, the selected rows or all rows as tab-separated text (pastes as columns in a spreadsheet); Export… writes CSV (UTF-8) through the file window. Row counts, SQLSTATE and messages go to a Messages tab, an error also as a red line under the editor. |
| R-SQL-9 | **A guard for changes** (2026-11-13). Before running `DELETE` or `UPDATE` without `WHERE`, or `DROP`, `TRUNCATE` or `ALTER`, the window names the statement and asks to confirm. The check reads the statement's first words and the presence of `WHERE` outside strings and comments; it only guards against slips, and says so. |
| R-SQL-10 | **SQL is an add-on** (2026-11-13; D15). The SQL window is the add-on "SQL" in Settings ▸ Add-ons, off by default (the owner, 2026-11-13: only those who want SQL see it and need Java); while it is off, Tools ▸ SQL… and the `sql` function are not there, Java is never looked for and no helper runs (D20). |
| R-SQL-14 | **A result tab per query** (2026-11-13). Each query run gets its own tab above the grid, named by its first words and row count ("SELECT * FROM ORDERS · 1000"); the newest is shown. Run all opens a tab per query it runs. Up to 10 tabs are kept, the oldest closing first; a tab closes with its ×, and each keeps its sort, filter, selection and Fetch more. |
| R-SQL-15 | **A row's values one under another** (2026-11-13). Double-clicking a row, or Enter on a selected one, shows its columns in a panel beside the grid: name, type, and the whole value wrapped (NULL apart from empty), each with a Copy button; the arrows step to the row above or below. |
| R-SQL-16 | **Filter and resize the grid** (2026-11-13). A filter field above the grid keeps the fetched rows that hold its text in any column, ignoring case, and says how many of how many are shown; Copy and Export take the rows shown. Dragging a column heading's right edge changes its width; double-clicking the edge fits it to the values shown. |
| R-SQL-18 | **Rows at a time and a query timeout** (2026-11-13). Settings ▸ Add-ons ▸ SQL: the rows fetched at first and by each Fetch more (default 1000, 100 to 100 000), and a query timeout in seconds (default none), after which the helper cancels the statement and says so. |
| R-SQL-19 | **SQL in colour** (2026-11-13). The editor shows keywords, strings, delimited names, numbers and comments in colours from the theme, in light and dark, as the user types, using the same scanner as statement splitting (`sql::text`); a large script stays responsive. |
| R-SQL-20 | **Several scripts in tabs** (2026-11-13). The editor holds several scripts, each in a tab named by its file or "Script n"; New tab (Ctrl+T), close (Ctrl+W, asking when a file's changes are not saved), Ctrl+Tab between them. Run works in the tab shown. The tabs, saved or not, come back for the same saved session the next time (kept with the settings, as the history; the owner, 2026-11-13). |
| R-SQL-21 | **Open and save SQL files** (2026-11-13). Open… (Ctrl+O), Save (Ctrl+S) and Save as… through the system's file window, UTF-8 text with the `.sql` extension; the tab shows the file's name and a dot while changes are not saved; opening a file that is open already shows its tab. |
| R-SQL-22 | **Format SQL** (2026-11-13). Ctrl+Shift+F formats the selection, or the statement under the cursor: keywords in capitals, each main clause (SELECT, FROM, WHERE, GROUP BY, ORDER BY, …) on its own line, the lists under it indented, strings, names and comments left exactly as written. A pure function in `parley_core::sql::text`, tested on statements with `æøå`, comments and nested selects. |
| R-SQL-23 | **Find and replace** (2026-11-13). Ctrl+F opens a find bar over the editor (next, previous, match case), Ctrl+H adds replace and replace all; Esc closes it. |
| R-SQL-28 | **A visible Run selection** (2026-11-13). While text is selected in the editor, Run reads "Run selection" and runs it, as it does today (R-SQL-7); otherwise the statement Run would execute, the one under the cursor, is shown with a faint background, so the operator sees what runs before pressing. |
| R-SQL-29 | **IBM i column headings** (2026-11-13). The helper asks JTOpen for extended metadata, so each column of a result also carries its column heading (COLHDG, set with `LABEL ON`, up to three parts of 20 characters) and its text, when the field has them. The grid's header shows the field names, the headings, or both (a choice above the grid, kept in the settings); hovering a heading shows the name, the heading, the text and the type. Copy and Export use what the header shows. Checked first on the owner's IBM i: that JTOpen returns the heading this way. |
| R-SQL-24 | **Snippets** (2026-11-13). A snippet is a `.sql` file, one per snippet, whose first comment lines hold `-- title:`, `-- tags:` and `-- about:`, then the SQL; the text is readable and editable outside Parley. They are kept in a `snippets` folder beside the settings, as macros are (D14), and optionally in a shared folder named in Settings ▸ Add-ons ▸ SQL (a network drive or a git checkout), so a team keeps one library. A name already used, a file that does not read, or a folder that cannot be written is named, not hidden. |
| R-SQL-25 | **The Snippets panel** (2026-11-13). Beside History, a Snippets tab lists the snippets by title with their tags, mine and shared apart; a search field matches title, tags, about and text, ignoring case. Double-click inserts a snippet at the cursor; Run runs it at once; the hover shows its about and SQL. "Save as snippet…" (from the editor, on the selection or the statement under the cursor) asks title, tags, about and mine or shared; mine and shared snippets can be edited, renamed and deleted (asking first). |
| R-SQL-26 | **Placeholders** (2026-11-13). `${name}` or `${name:default}` in a snippet is asked for in a small form when the snippet is inserted or run, one field per name, the last value used in this run of Parley offered first; the values are put in as typed (the operator writes the quotes in the snippet where SQL needs them). |
| R-SQL-27 | **"Did you know" snippets from IBM i Services** (2026-11-13). Parley comes with a starter set of read-only snippets, tagged "did you know", that show what IBM i Services can answer: the busiest active jobs, a job's job log, spooled files of a user, locks on an object, the PTF level and group PTFs, users and their last sign-on, system status, network connections, the history log, the largest objects in a library, table statistics. Each names the IBM i release it needs; each was run on the owner's IBM i (7.3) or marked as needing a later release. Copy to mine to change one. |
| R-SQL-30 | **CL commands** (2026-11-13). A statement that starts with `CL:` (as in ACS Run SQL Scripts, so its scripts run as they are) runs the rest as a CL command through `QSYS2.QCMDEXC` in the SQL job; it is coloured as a command, goes into the history, and its completion or error message goes to Messages. Run all runs it in its place. |
| R-SQL-31 | **Message help and the job log** (2026-11-13). An SQL error in Messages shows its message ID (SQL0204), the first-level text, and, on asking, the second-level text (cause and recovery) from `QSYS2.MESSAGE_FILE_DATA` for QSQLMSG. "Job log" shows the SQL job's newest messages (`QSYS2.JOBLOG_INFO` for `*`), so a failed statement's detail can be read without a 5250 session. |
| R-SQL-32 | **Library list and current schema** (2026-11-13). The top bar shows the SQL job's current schema; a menu lists its library list (`QSYS2.LIBRARY_LIST_INFO`) and sets the current schema (`SET SCHEMA`) or adds a library (`ADDLIBLE`). Read again after a statement that may change them (`SET SCHEMA`, `CL:`). |
| R-SQL-33 | **A second connection for the catalog** (2026-11-13; D21). At Connect the helper signs on twice with the password typed, then forgets it: the first job runs the operator's statements, the second only reads the catalog for R-SQL-34..37, so browsing never waits for a running query. Each answer says which job it came from; the top bar names both jobs. If the second sign-on fails, the window works without the browser and says why. |
| R-SQL-34 | **The schema browser** (2026-11-13). A Database tab beside History and Snippets: the library list and the libraries pinned (kept per session; any library can be found by name and pinned), each opening to tables, views, indexes, procedures and functions (`QSYS2.SYSTABLES`, `SYSINDEXES`, `SYSROUTINES`), each table to its columns with type, heading and text. A search filters by name; double-click inserts the qualified name at the cursor; read lazily, a level at a time, with Refresh. |
| R-SQL-35 | **The DDL of an object** (2026-11-13). On an object in the browser, "Show SQL" opens its DDL (`QSYS2.GENERATE_SQL`) in a new script tab; "Select first rows" puts a `SELECT … FETCH FIRST 100 ROWS ONLY` there and runs it. |
| R-SQL-36 | **Completion** (2026-11-13). As one types a name in the editor, after a `.` or a few letters, a list offers the libraries, tables and views known to the browser, and, after `table.` or an alias declared in the statement, its columns (with type and heading); Up/Down choose, Tab or Enter accepts, Esc closes, typing goes on. SQL keywords are offered too. Names come from the browser's cache, read on the second connection when missing; never blocks typing. |
| R-SQL-37 | **Names on hover** (2026-11-13). Hovering a table or view name in the editor shows its text and columns (name, type, heading), from the browser's cache. |
| R-SQL-38 | **Copy as Markdown, INSERT or JSON** (2026-11-14). Beside Copy, a menu copies the rows shown (or the selected rows) as a Markdown table, as `INSERT INTO lib.table (…) VALUES (…)` statements (the table named from the query when it reads one table, else asked), or as a JSON array of objects keyed by column name. Nulls stay null (`NULL`, `null`, empty in Markdown); numbers are not quoted; text is escaped for each format (`\|` in Markdown, `''` in SQL, JSON escapes). |
| R-SQL-39 | **Binary values as hex and EBCDIC** (2026-11-14). A `FOR BIT DATA` or `BINARY` value (sent as hex) shows in the row detail as hex bytes in groups beside the same bytes read as EBCDIC in a chosen code page (the session's by default), unprintable bytes as `.`. |
| R-SQL-40 | **A form for parameter markers** (2026-11-14). Running a statement with `?` or `:name` markers (outside strings and comments) opens a form with a field per marker (`:name` once per name); Run sends the statement prepared with the values as its parameters (D23), an empty field as null when ticked. The values are remembered per statement text for the session's window. |
| R-SQL-41 | **Compare two results** (2026-11-14). From a result tab, "Compare with…" picks another tab with the same column names; rows are matched by key columns (the first column unless others are chosen); a result tab then lists rows only in the first, only in the second, and rows whose other values differ, with the differing cells marked. |
| R-SQL-42 | **Quick charts** (2026-11-14). A Chart view of a result: the first text or date column along the bottom, the numeric columns chosen as bars or lines, from the rows fetched; a legend; light and dark. Drawn with `egui_plot` (D23). |
| R-SQL-43 | **One statement on several systems** (2026-11-14; *removed with Parley's SQL window by R-SQL-70, D30*). "Run on…" in the SQL window lists the other saved sessions; ticked ones are signed on in the window (a user and a password typed for each, used once and forgotten, D16), each in a helper of its own. "Run on all" runs the statement under the cursor on the window's system and every ticked one at once, only if it reads (`SELECT`, `VALUES`, `WITH`; never `CL:`, never two statements), and opens a result tab per system named after it; an error on one system is said in Messages under its name and the others go on. A system's rows are its first block; more are not fetched (said in the tab). The sign-ons last until the window closes or the system is unticked (D24). |
| R-SQL-44 | **An SQL assistant** (2026-11-14). An "Ask" field over the editor takes a question in plain words; Parley sends it to Claude (`claude-opus-5-5`) with the current schema and library list, and lets the model look up a library's tables and a table's columns through the schema browser's catalog (names, types, headings and texts only). The answer's SQL goes into a new script tab with the model's short explanation as comments; nothing runs by itself. Before the first question the window says what is sent and where; a request in flight can be cancelled; errors (no key, refused, network) are said plainly (D25). |
| R-ADD-3 | **The SQL assistant is an add-on, off by default** (2026-11-14. *Changed by R-SQL-48: the switch is on Settings ▸ SQL assistant, not Add-ons, and the key may also be in the keychain.*) "SQL assistant" in Settings ▸ Add-ons ("Ask Claude to write SQL from plain words; sends table and column names to Anthropic"), off until turned on; it needs the SQL add-on and an Anthropic API key in the environment variable `ANTHROPIC_API_KEY`, which Parley reads when asking and never stores. Turned off, nothing of it shows and nothing is sent (D25). |
| R-SQL-45 | **Parley SQL, the SQL window on its own** (2026-11-14; D26). A second program, `parley-sql`, built from this repository beside `parley` and shipped in the same installers, opens the SQL window of R-SQL-6 in its main window (title "Parley SQL", or "*connection* – Parley SQL"), with no 5250 session. Above it a header in Parley's look (R-UI-15): the icon and "Parley SQL", File (New connection…, Edit connections…, Connect to ▸, Disconnect, Exit) and Help (Check for updates…, the version); on the right a gear that opens Settings, and while a window is open a pill with the connection's name, host, a lock for TLS and a dot for where it is (not signed on, signing on, ready), whose menu edits it or disconnects. Below, a status bar: Offline and why the last window closed; otherwise not signed on, signing on, Ready or Running…, the last error, and on the right the job (user and release on hover), Autocommit off or Uncommitted changes, TLS or Not encrypted, and the CCSID. The window's Close is Disconnect and leads back to the start screen; closing the program with changes not committed asks first (R-SQL-5). Everything else is the add-on's window: the same helper, history, scripts, snippets (the same folder as Parley's), schema browser and assistant; but not Run on… (R-SQL-43): Parley SQL works on one connection at a time (D26). Without the helper or Java it says why, as R-SQL-12. `parley-sql CONNECTION` opens that connection's sign-on. |
| R-SQL-46 | **Saved connections in Parley SQL** (2026-11-14; D26). The start screen lists the saved connections as cards (name; host, TLS, user) with Edit… and Connect, and New connection….
