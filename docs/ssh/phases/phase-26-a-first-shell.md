# Phase 26 — A first shell

> Finished phase of Parley SSH. Open work: [../ROADMAP.md](../ROADMAP.md); index of requirements: [../REQUIREMENTS.md](../REQUIREMENTS.md).

## Story

The smallest Parley SSH that is useful: open `parley-ssh`, type a host, user name and password, check the host key,
and work in a shell with full-screen programs (vim, less, htop, tmux) in colour. R-SSH-1..10.

**Status:** Done (2026-11-16), checked by the owner on Windows, macOS, Linux and WSL: R-SSH-1, R-SSH-2, R-SSH-3, R-SSH-4, R-SSH-5, R-SSH-6, R-SSH-7, R-SSH-8, R-SSH-9, R-SSH-10.

## Requirements

| ID | Requirement |
|---|---|
| R-SSH-1 | **Parley SSH, a program of its own** (D41). Two new crates: `parley-ssh-core` (the SSH client and the terminal emulation; no UI) and `parley-ssh-ui` (the window, on `parley-ui-egui`'s look: theme, dialogs, icons, header, status bar, the settings frame with Appearance and About). A third binary `parley-ssh` in `parley-app`, with app id `parley-ssh` and settings of its own. `cargo deny` keeps the programs apart (R-P-5): Parley 5250's and Parley SQL's crates never use the SSH crates, and the SSH crates use neither program's engine nor Parley SQL's UI. `make run-ssh` starts it; the installers on all three OSes install it beside `parley` and `parley-sql`, with its own menu entry and icon (Start menu shortcut on Windows, `.desktop` entry in the `.deb`), and `parley-ssh` works in a new terminal as R-NF-2 makes `parley-sql` work; `parley --ssh [ARGS]`, or a link named `parley-ssh` to the AppImage, starts Parley SSH (2026-11-16, asked by the owner). |
| R-SSH-2 | **Connect** (RFC 4253). A start screen as Parley SQL's, with host, port (22) and user name; SSH-2 only. Offered by default, in this order: key exchange `curve25519-sha256`, `ecdh-sha2-nistp256/384/521`, `diffie-hellman-group16-sha512`, `diffie-hellman-group14-sha256`; host keys `ssh-ed25519`, `ecdsa-sha2-nistp256/384/521`, `rsa-sha2-512`, `rsa-sha2-256`; ciphers `chacha20-poly1305@openssh.com`, `aes256-gcm@openssh.com`, `aes128-gcm@openssh.com`, `aes256-ctr`, `aes128-ctr`; MACs `hmac-sha2-256-etm@openssh.com`, `hmac-sha2-512-etm@openssh.com`, `hmac-sha2-256`, `hmac-sha2-512`; strict key exchange (`kex-strict-c-v00@openssh.com`, the Terrapin fix) when the server offers it. A server with nothing in common, a refused connection, a timeout or a disconnect is told in plain words with the server's reason. |
| R-SSH-3 | **Host keys are checked** (RFC 4251 §4.1). Known keys are read from OpenSSH's `~/.ssh/known_hosts` (hashed entries and `[host]:port` too) and from Parley SSH's own `known_hosts` beside its settings, where it writes new ones (OpenSSH's file is never changed). A key not seen before opens a dialog with the host, the key type and its SHA-256 fingerprint: Accept and save, Connect once, or Cancel. A key that differs from the saved one opens a warning with both fingerprints and only Cancel as the main action; to go on the user removes the saved key in that dialog by a separate, explicit step and then sees the new-key dialog. No setting turns the check off. |
| R-SSH-4 | **Sign on with a password or keyboard-interactive** (RFC 4252, RFC 4256). The methods the server lists are tried in the order keyboard-interactive, password; each prompt is shown as the server sends it (name, instruction, prompts, echo or hidden), so one-time codes work. The password is asked each time and never kept (D16), held in `parley_ssh_core::Secret` (hidden from `Debug`, wiped when dropped; *changed 2026-11-16: the SSH crates do not use Parley 5250's engine, R-SSH-1*), and never logged. A server's banner (`SSH_MSG_USERAUTH_BANNER`) is shown before the prompts. A server that asks for a new password (`SSH_MSG_USERAUTH_PASSWD_CHANGEREQ`) gets a change-password dialog (*not yet: russh 0.65 cannot receive that message; servers that change passwords through PAM ask through keyboard-interactive, which works*). |
| R-SSH-5 | **A shell** (RFC 4254 §6). A session channel with a pseudo-terminal (`TERM=xterm-256color`, the window's columns and rows, UTF-8 terminal modes) and a shell. A resized window sends `window-change`. When the shell ends, the status bar says so with its exit status or signal and the screen stays readable; Restart session (Ctrl+Shift+R) connects again with the same settings, asking for the password again. |
| R-SSH-6 | **xterm emulation** (ECMA-48, DEC STD 070, xterm's ctlseqs). Sans-I/O in `parley-ssh-core`: bytes in, a screen of cells out, replies out. C0 controls; cursor movement and saving (`CUP`, `CUU`…, `DECSC`/`DECRC`); erase and insert/delete of characters and lines; scrolling regions (`DECSTBM`) and index; tab stops; SGR: bold, faint, italic, underline (single, double, curly), blink, inverse, hidden, strike-through, 16, 256 and 24-bit colours; DEC modes: cursor keys (`DECCKM`), auto-wrap (`DECAWM`), origin (`DECOM`), cursor shown (`DECTCEM`), the alternate screen (47, 1047, 1049), bracketed paste (2004), focus events (1004); DEC Special Graphics line drawing (`ESC ( 0`); the window title (OSC 0 and 2); device status and attribute replies (`DSR`, `DA1`, `DA2`) as xterm's; `RIS` and `DECSTR`. UTF-8 with wide characters (East Asian Wide, emoji) in two cells and combining marks in their base cell. Unknown sequences are skipped, never shown as text, and never panic. Tested with recorded output of vim, less, htop, tmux and `vttest`'s first screens, and with truncated and malformed sequences. |
| R-SSH-7 | **Keys go to the host as xterm sends them.** Printable characters as UTF-8 (AltGr characters too); Enter `CR`; Backspace `DEL` (0x7F); Tab, Shift+Tab (`CSI Z`); Escape; Ctrl+letter and Ctrl+@, [, \, ], ^, _; Alt+key as `ESC` then the key; the arrows, Home and End in normal and application mode; Insert, Delete, Page Up and Page Down (`CSI 2~` …); F1–F12 with Shift, Ctrl and Alt as xterm's modifier parameter. Parley SSH's own shortcuts use Ctrl+Shift (copy, paste, find, new session, restart), so Ctrl+C, Ctrl+V and the rest reach the host. A shortcut sheet lists them, as Parley's (R-UI-17). |
| R-SSH-8 | **The screen and its scrollback.** The terminal font of Parley 5250 (bundled JetBrains Mono or an installed font, `parley-ui-egui`'s `fonts`), with bold (drawn heavier and, for the eight normal colours, bright; no bold face is bundled) and italic (*not yet: no italic face is bundled; with R-SSH-20's fonts*); a block cursor that blinks; Parley's dark and light terminal colours (the 16 ANSI colours of each). Lines that scroll off the top are kept (10,000 by default; not for the alternate screen) and read with the mouse wheel, the scroll bar and Shift+Page Up/Down; a key that goes to the host scrolls back to the bottom. The window's columns and rows follow its size; the status bar shows them while it is resized. |
| R-SSH-9 | **Copy and paste.** Drag selects (across the scrollback too), a double click a word, a triple click a line; Ctrl+Shift+C or the right-click menu copies, as text without the trailing blanks of each line and with wrapped lines joined. Ctrl+Shift+V, Shift+Insert or the menu pastes; inside bracketed paste mode the text is wrapped in `CSI 200~`/`CSI 201~`, otherwise line ends are sent as `CR`. Pasting more than one line outside bracketed paste asks first (it may run commands), with "don't ask again" per session. While a remote program reads the mouse (R-SSH-18), Shift+drag still selects. |
| R-SSH-10 | **The window around the screen.** The header and status bar of Parley SQL: the session pill (`user@host`, connected or not), menus Session (New, Restart, Disconnect, Close), Edit (Copy, Paste, Copy all, Clear scrollback, Reset terminal), View and Help; the status bar shows the state, the size and, on hover, the algorithms in use and the host key's fingerprint. Settings with Parley's Appearance (theme, text size) and About (version, the update check, D13) pages. Closing the window while connected asks first (setting). Works in light and dark. |
