| IDEA-43 | *(Picked 2026-11-16 for Phase 31: → R-SSH-53..57, D48.)* **Transfers with rsync instead of SFTP** (the owner, 2026-11-16: "instead of SFTP or FTP … rsync for transferring between servers"). Would change Phase 31 (R-SSH-35, R-SSH-36) when picked. Thoughts: (1) **Server to server, direct:** Parley runs `rsync -az --info=progress2` on server A over an exec channel, pushing to server B; A signs on to B with the user's agent through agent forwarding (R-SSH-13), so no key is copied to A and the data never passes through the desktop. (2) **When A cannot reach B:** Parley forwards a port back from A to B through itself (remote forwarding, R-SSH-31), and A's rsync goes through that tunnel; slower, but works across networks. (3) **Desktop to server:** needs an rsync on the desktop (most Linux and macOS have one; Windows has none by default), started with Parley SSH as its transport; else fall back to SFTP for this one case. (4) **The UI:** a Transfer panel with a source and a target, each a session (pane) and a path; a dry run first (`--dry-run --itemize-changes`) listed as what will be added, changed and deleted; then progress, speed and time left from `--info=progress2`, Cancel, and resume with `--partial`; switches for delete extra files, keep permissions and excludes; transfers saved by name to run again, and in the palette (R-SSH-48). (5) **Checks:** that both servers have rsync 3.1 or later (`rsync --version`), said in plain words when not. |
