# Parley SSH decisions

> Decisions are numbered across all three programs (Parley 5250, Parley SQL and Parley SSH); the next free number is on [../ROADMAP.md](../ROADMAP.md)'s last line.

Decisions D1–D18 and D36–D38 (language, crates, TLS, the look, no saved passwords, two programs apart, the alarm) are
in [../DECISIONS.md](../DECISIONS.md) and bind this work too.

| ID | Question | Decision | Alternatives considered |
|---|---|---|---|
| D41 | Should the Parley family get an SSH client, and how? | **Yes: Parley SSH** (the owner, 2026-11-16), an SSH client that does what PuTTY does, then more, in the look Parley 5250 and Parley SQL share (D12). Built as D36 built Parley SQL: its own engine crate `parley-ssh-core` and UI crate `parley-ssh-ui` on `parley-ui-egui`'s look, a third binary `parley-ssh` in `parley-app`, its own settings and app id `parley-ssh`, in this repository and in Parley's releases. `cargo deny` keeps it apart from the other two programs (R-P-5). Its plan is [ROADMAP.md](ROADMAP.md). | A separate repository (the shared look would drift, D12); an add-on inside Parley 5250 (an SSH user needs no green screen). |
| D42 | Which SSH library (§6 question 1)? | **`russh`** (the owner, 2026-11-16): pure Rust, Apache-2.0, with `russh`'s key and agent support. It needs tokio, which D4 kept out of Parley; tokio runs only inside `parley-ssh-core`'s network thread (a current-thread runtime), so the UI and the terminal engine stay as D4's: no async outside that thread. | `ssh2` (libssh2 and OpenSSL: C code on three OSes and a second TLS stack beside D6's rustls). |
| D43 | How is the terminal emulated (§6 question 2)? | **A screen model of Parley SSH's own over the `vte` parser** (the owner, 2026-11-16), sans-I/O in `parley-ssh-core` (bytes in, screen out, replies out), tested byte for byte as `parley-core` is (R-P-2). | `alacritty_terminal` (large, its API follows Alacritty, its screen does not fit Parley's widgets). |
| D44 | May Parley SSH sign on with keys (§6 question 3)? Reads D16 for SSH. | **Yes: key files and an agent that is already running** (the owner, 2026-11-16): the key and the agent are the user's, as OpenSSH uses them. Parley SSH keeps no password or passphrase, asks for them each time, and has no agent of its own (Later). | Passwords only; an agent of Parley SSH's own from the start. |
| D45 | One window per session, or tabs (§6 question 4)? *Replaced by D47 (2026-11-16).* | **One window per session, as PuTTY** (the owner, 2026-11-16; R-SSH-10, R-SSH-15). Tabs and split panes stay an idea (IDEA-37). | Tabs from the start. |
| D46 | What is Parley SSH measured against? Changes the roadmap's §1 (PuTTY as the yardstick) and Phase 28. | **Today's SSH clients and terminals, not PuTTY** (the owner, 2026-11-16: "PuTTY is old school … features used in 2026 and a modern, lean UI"): Windows Terminal, iTerm2, WezTerm and Termius are checked when a requirement is planned; settings are lean, with good defaults and a setting only for what people commonly change. Phase 28 keeps the mouse, find, a simple bell and logs; PuTTY's keyboard styles, selection options, other character sets and terminal options are dropped (R-SSH-17, R-SSH-21..23); appearance becomes themes and fonts (R-SSH-20, Phase 37). The owner chose the next features: tabs and split panes, `~/.ssh/config`, shell integration, a command palette; then themes and fonts, snippets and broadcast, reconnect and restore. | PuTTY parity, with every option behind an Advanced page. |
| D47 | One window per session, or tabs (D45 again)? Changes D45, R-SSH-10, R-SSH-15. | **Tabs and split panes in one window** (the owner, 2026-11-16), as Windows Terminal and iTerm2; New window still starts another `parley-ssh`. | One window per session (D45). |
| D48 | How does Parley SSH transfer files (Phase 31)? Changes R-SSH-35, R-SSH-36. | **With rsync, not SFTP or SCP** (the owner, 2026-11-16, IDEA-43): server to server directly with agent forwarding, through Parley SSH when the servers cannot reach each other, and between the desktop and a server with the desktop's rsync; in the build order after Phase 39. | An SFTP panel (R-SSH-35) with SCP (R-SSH-36). |
| D49 | How do themes and fonts work in Parley SSH (Phase 37, R-SSH-20)? | **Bundled themes for the terminal only, and bundled fallback faces** (the owner, 2026-11-16): the roadmap's set of themes (Parley dark and light, Solarized dark and light, Nord, Dracula, Gruvbox dark and light, Catppuccin Latte and Mocha, Tokyo Night and Tokyo Night Day), colouring the screen only; the header, tabs, dialogs and status bar keep the shared look (D12). Symbols Nerd Font Mono (MIT) and Noto Emoji, monochrome (OFL), are bundled as fallbacks, and JetBrains Mono's Bold, Italic and Bold Italic faces (OFL) for real bold and italic. | More themes (One Dark, Rosé Pine, Kanagawa, Everforest); importing Windows Terminal or iTerm2 theme files; the theme over the whole window; fallbacks from installed fonts only, or Nerd symbols only; bold drawn heavier and no italic. |
| D50 | How do snippets and restore work (Phases 38 and 39)? | **Snippets in Parley SSH's settings, sent from a menu and a picker; restore brings back layout and sessions** (the owner, 2026-11-16): snippets are one list in the settings (Settings ▸ Snippets, export and import as one file), with `{{name}}` and `{{name:default}}` placeholders asked when sent; a Snippets menu, a search-as-you-type picker (Ctrl+Shift+S) and a key per snippet send them until the palette (Phase 36) lists them too. Restore reopens the tabs, their split panes and sizes and each pane's session, with empty screens; no output is saved. | Snippet files in a folder, as Parley SQL's; a snippets side panel; a menu only; `${name}` placeholders; restoring the scrollback too. |
| D51 | What is left of Phase 29 (D46 asked for it to be trimmed)? Changes R-SSH-26..29. | **Keepalives and the IP version, a remote command with environment variables and the terminal type, proxies, and compression and rekeying; no older algorithms** (the owner, 2026-11-16). SOCKS 5 and HTTP CONNECT proxies and a local proxy command (also `ProxyCommand` from `~/.ssh/config`), proxy passwords asked and never kept. Jump hosts were done as R-SSH-43. Algorithm lists and the older algorithms (`diffie-hellman-group1-sha1`, `ssh-rsa` with SHA-1, `aes-cbc`, `3des-cbc`) are not offered at all, so servers that speak only those cannot be reached. Dropped from PuTTY: SOCKS 4, terminal modes, no pseudo-terminal, a user name asked, which hosts go direct. | A switch for older algorithms; PuTTY's ordered algorithm lists with a warning line. |
