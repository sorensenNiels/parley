# Parley requirements

> The agreed text of every requirement that is implemented **and verified**: when one is, its row moves here from
> [ROADMAP.md](ROADMAP.md) (open requirements) and [FEATURES.md](FEATURES.md) records how it was verified.
> Look a requirement up by ID (`grep -n "R-NET-1 " docs/REQUIREMENTS.md`) rather than reading the whole file.

| ID | Requirement |
|---|---|
| R-NET-1 | Open a TCP connection to a host and port (default 23) and negotiate TN5250 per RFC 1205 / RFC 2877: terminal type (`IBM-3179-2`), binary, end-of-record. |
| R-NET-2 | TLS connections (default port 992), checking the server certificate; a session can trust a given CA certificate. |
| R-NET-3 | Request a device name through the NEW-ENVIRON option (RFC 2877), and show the host's error when it is refused. |
| R-NET-4 | *(Removed 2026-11-12 by R-NET-7, D16: Parley no longer signs on by itself or keeps passwords.)* Auto sign-on (2026-11-12). *Screen*: on the first screen whose first two input fields are a user field and a non-display field, type the user and password and press Enter, once per connection. *Bypass*: answer the host's NEW-ENVIRON SEND with `VAR USER`, `USERVAR IBMRSEED` (a random client seed) and `USERVAR IBMSUBSPW` (the password substitute) per RFC 4777 section 5, DES (5.1) or SHA-1 (5.2) as the session's password-encryption setting says (QPWDLVL 0–1 or 2–3); the host needs QRMTSIGN `*VERIFY` or `*SAMEPRF`. Only when the host sends its seed: the password never goes in clear text. Checked against the RFC's test vectors and its example negotiation, byte for byte. |
| R-NET-5 | Keep-alive (2026-11-12): a session with it on sends telnet NOP (IAC X'F1') after 60 s without sending anything, so firewalls keep an idle connection. |
| R-NET-7 | **No auto sign-on, no saved passwords** (D16; replaces R-NET-4). Parley never signs on by itself: the operator signs on on the host's sign-on screen, or a macro does, asking for the password at its `password` step (R-KEY-3, R-KEY-4). The session dialog has no user, password, auto sign-on or password-encryption fields, and Parley never sends a user or password substitute in NEW-ENVIRON (RFC 4777), even when the host offers a seed. Passwords Parley 0.2 saved in the operating system's keychain are deleted at the first start of this version, for every saved session; one that cannot be deleted is reported (`parley:` on the terminal) and tried again at the next start. Old settings with sign-on fields still load (the fields are ignored). R-NET-6 (why a bypass sign-on failed) is dropped. Tested: telnet's answer to RFC 4777's request with a seed holds only the device name; a session on a sign-on screen sends nothing until a key; the session dialog asks for no user or password. |
| R-NET-10 | **Reconnect when the connection drops** (2026-11-15, from IDEA-16; the owner chose automatic retries, per session). A session setting "Reconnect when the connection drops", off by default. When it is on and the connection ends by a network failure (a read, write or TLS error; not when the host ends the job and closes the connection, not on Disconnect, and not when the first connect fails), Parley connects again after 2, 4, 8, 16, 32 and then every 60 s; the status bar shows "Reconnecting in 8 s" with Cancel, and Connect again connects at once. A connect that fails waits for the next try. Once connected, the session's Run macro runs again as on any connect (R-KEY-4). The Offline note says whether the network failed or the host ended the session. |
| R-DS-1 | Parse the 5250 data stream commands needed for sign-on and menus: Clear Unit, Write To Display (with its orders: Set Buffer Address, Start of Header, Start of Field, Insert Cursor, Repeat to Address), Read MDT Fields, Read Input Fields. |
| R-DS-2 | A screen model: character buffer, field table (attributes, input/output, mandatory, bypass), cursor and the operator-information line. |
| R-DS-3 | Send AID keys (Enter, F1–F24, Page Up/Down, Clear, Help, Sys Req, Attention) with the modified fields. |
| R-DS-4 | The other commands an IBM i sends in normal use: Write Error Code (message on the error line, keyboard inhibited until Reset), Save Screen / Restore Screen, Roll, Clear Unit Alternate (27×132), Clear Format Table, Read Immediate, Read Screen Immediate, and the reply to the 5250 Query structured field. Erase to Address, Transparent Data and Move Cursor orders. |
| R-DS-5 | **The data stream checked against the manual** (2026-11-12, from IDEA-1). Each point Phase 1 built from memory is checked against IBM's 5250 Functions Reference (SC30-3533) and cited next to the code: Start of Header clears the format table; Read MDT Fields sends nulls as blanks; a signed numeric field is sent without its sign position, a minus making the last digit's zone X'D'; the bytes of the reply to the 5250 Query. A point that differs is fixed, with a test that fails without the fix; a point the manual leaves open is noted in the code. |
| R-DS-6 | **Save and Restore Partial Screen** (2026-11-15, from IDEA-7; SC30-3533-04 §15.22, §15.24). Save Partial Screen (ESC X'03' and five bytes: flag, top row, left column, depth, width) is answered as Save Screen is (D7): Parley keeps the whole screen, as the 5494 does ("saves the entire display screen in all cases, ignoring these four parameters"), and replies with opcode Save Screen and `ESC X'13'`, a 2-byte length counting itself, and its id; the reply goes after the rest of the record has been carried out. Restore Partial Screen (ESC X'13', a 2-byte length counting itself, the data) puts back what was saved, as Restore Screen does, and the commands after it in the record are carried out. Restore data Parley did not make, or a length that runs past the record, is reported as a bad record. |
| R-DS-7 | **Read MDT Immediate Alternate** (2026-11-15, from IDEA-7; SC30-3533-04 §15.20, RFC 1205 §5.3). ESC X'83', with no control characters, is answered at once, without waiting for an AID key or unlocking the keyboard: the cursor's row and column, AID X'00' (RFC 1205), then each modified field after a Set Buffer Address, its leading and embedded nulls kept and trailing nulls left out, as Read MDT Fields Alternate. The query reply says Parley supports it (device capability byte 0, bit 7). |
| R-DS-8 | **Function keys that send no field data** (2026-11-15, from IDEA-4; SC30-3533-04 §15.6.9 "Start of Header Order"). When a Start of Header has all seven bytes, its bytes 5–7 are the command key switches: a set bit (byte 5 bits 0–7 for F24–F17, byte 6 for F16–F9, byte 7 for F8–F1, bit 0 the high-order bit) makes that function key send only the cursor's row and column and its AID, without field data, as tn5250 and tn5250j read the manual's "prevents input data … from being returned". A shorter Start of Header, Clear Format Table and Clear Unit return every key to sending data; Save/Restore Screen keep the switches with the screen. The keys still lock the keyboard and wait for the host as before. |
| R-EBC-1 | Convert EBCDIC to and from Unicode for CCSID 37 (US) and 277 (Danish/Norwegian), and their euro variants 1140 and 1142; the session chooses the CCSID and announces it to the host (`KBDTYPE`, `CODEPAGE`, `CHARSET`, RFC 4777). |
| R-KEY-1 | A default keyboard mapping: Enter; Shift+Enter or Ctrl+Enter for Field Exit; Ctrl++ / Ctrl+- (and + / - in signed numeric fields) for Field+ / Field-; a Ctrl key pressed alone or Ctrl+R for Reset; Tab / Shift+Tab between fields; F1–F24 (Shift+F1–F12 for F13–F24); Page Up / Down to roll; Esc / Shift+Esc for Attention / System Request; Insert, Delete, Backspace, Home, End, Ctrl+End (Erase EOF), arrows. The field rules of the field format word: bypass, alpha/numeric/digits/signed numeric only, monocase, auto enter, field exit required, right adjust. (Right Ctrl for Enter, as in IBM's emulators, is not possible: egui does not tell left and right Ctrl apart.) |
| R-KEY-2 | **Keyboard maps** (from IDEA-9). Settings ▸ Keyboard lists every 5250 key and Parley action (Enter, Field Exit, Field+/-, Reset, F1–F24, Attention, System Request, Roll, Erase EOF, Insert, Copy, Paste, …) with the PC keys bound to it; select one and press a key to add a binding, remove a binding, "Restore defaults". The map R-KEY-1 defines is the built-in **Default** map, which cannot be changed; the user can copy it under a new name, edit, rename and delete their own maps. A key bound twice in one map is flagged and the new binding wins only after the user confirms. A key egui cannot tell apart (e.g. left and right Ctrl, R-KEY-1) cannot be bound. The session dialog has "Keyboard map" (Default unless chosen); a session whose map was deleted falls back to Default. Maps are saved with the settings. *As built (2026-11-12): a key matches only with the same Ctrl, Alt and Shift (Shift is ignored on keys that type a character, whose shifted character egui already names); a key that types a character can be bound only with Ctrl and without Alt (AltGr); Ctrl+C, Ctrl+V and Ctrl+X are the system's clipboard keys, always copy and paste and cannot be bound (egui never reports them as keys), but Copy and Paste can get more keys; while the Macros add-on is on, the map also holds Record macro (start and stop) and a Run macro per macro; renaming a map or a macro moves its keys and sessions along.* |
| R-KEY-3 | **Record a macro** (from IDEA-11). Tools ▸ Record macro starts recording on the connected session; the status bar shows "REC" until Tools ▸ Stop recording, then Parley asks for a name and whether the macro is only for this session (else for all). A macro is the 5250 keys and text typed (not mouse clicks), with a `wait` step after each AID key, Attention and System Request. Keys the session refuses are not recorded, nor the Reset that clears their error. Text typed into a non-display field is never recorded: it becomes one `password` step, which asks for the password each time the macro is played (Parley keeps none, R-NET-7). Recording stops when the connection ends or on Disconnect, and the name is asked then. Macros are saved as text files (D14), one per macro, so users can edit and share them; renaming a session moves its macros along. *A key in the keyboard map starts and stops recording (R-KEY-2).* |
| R-KEY-4 | **Run a macro** (from IDEA-11). Tools ▸ Run macro ▸ lists the macros for all sessions and for this one; the session dialog's "Run macro" (disabled since R-UI-5) runs one at connect, from the first unlocked screen, so the macro can sign on itself. The status bar shows "⏵ Macro" while one runs. A running macro waits at each `wait` step until the host has answered and unlocked the keyboard (giving up after 30 s with a message), stops at an operator error (the error stays on screen), and stops when the user presses Reset or Esc (Attention), chooses Tools ▸ Stop macro, or the connection ends; other keys are ignored while it runs. Tools ▸ Macros… lists the macros to rename or delete, shows their folder (Open folder, Copy path, Read again for files edited by hand). A macro file that cannot be read is listed with the reason (and the line) and cannot be run. *A key in the keyboard map can run a given macro (R-KEY-2).* *(Open folder removed 2026-11-12 by R-KEY-7: Edit, Import and Export replace it.)* |

The settings keep only the ids that differ from their default (turned on, or turned off), so an add-on a later version brings starts with its default and an id this version doesn't know still loads. A switch takes effect when the dialog is saved; Cancel and the close button leave the add-ons as they were; Restore defaults on the page puts every add-on back to its default. |
| R-ADD-2 | **Macros are an add-on, on by default** (D15). "Macros" in Settings ▸ Add-ons ("Record keystrokes and play them back, also when a session connects."). While it is off, nothing of it is in the app: the Tools menu has no Record macro, Run macro ▸, Stop macro or Macros…, the status bar has no macro box, the session dialog has no Run macro, a session's Run macro is not run when it connects (the choice is kept for when the add-on is on again), and the macro folder is not read. Turning it off while connected stops a running macro, and ends a recording by asking for its name as Stop recording does, so nothing is lost; the Macros… dialog closes. Macro files stay where they are. *(Changes R-KEY-3, R-KEY-4: their menu items and the session dialog's Run macro exist only while the add-on is on.)* |
